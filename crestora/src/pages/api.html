Basics

Conventions

Everything goes over HTTPS to one base URL, and everything comes back as JSON. A few habits hold across the whole API:

  • JSON both ways. Send Content-Type: application/json with a body; responses are UTF-8 JSON.
  • Times in UTC. Timestamps are ISO 8601, like 2026-12-10T17:00:00Z; plain dates are YYYY-MM-DD.
  • IDs say what they are. ln_ a lane, sp_ a spark, vr_ a version, cm_ a comment, lc_ a launch, ev_ an event.
  • Retries are safe. Send an Idempotency-Key header with a POST, and a repeat within 24 hours returns the first response instead of a duplicate.
  • v2 is stable. Breaking changes only arrive in a new version, with 12 months of overlap. New fields can appear any time, so ignore the ones you don’t know.

Every response carries

200 OK 
HTTP/2 200
content-type: application/json; charset=utf-8
crestora-version: 2026-11-20
request-id: req_8Kd2PqT4
x-ratelimit-limit: 600
x-ratelimit-remaining: 597
x-ratelimit-reset: 1795789320

Basics

Authentication

Every request carries a token in the Authorization header. Create tokens under Settings → API: personal tokens act as you, and app tokens act as an integration installed on a crew.

Live tokens start with crst_live_. Tokens from the sandbox start with crst_test_ and only ever touch sample data. Keep tokens out of code you share; if one leaks, revoke it in Settings → API and it stops working within a minute.

Each token carries scopes. A request without the scope it needs gets 403 insufficient_scope, and the message names the missing scope.

Scopes

ScopeGrants
lanes:readList and read lanes, their stages and Blueprints.
lanes:writeCreate, update, move and delete lanes.
sparks:writeAdd sparks to a board or a lane.
versions:writeAdd new versions to a lane.
comments:readRead the notes left on versions.
comments:writeLeave notes and replies on versions.
launches:writeSchedule launches and their channels.

The JavaScript and Python samples below reuse the small api helper and session set up here.

const token = process.env.CRESTORA_TOKEN;

async function api(path, { method = "GET", body } = {}) {

Basics

Rate limits

Each token can make 600 requests per minute, counted over a sliding window. Every response says where you stand.

Go over and you get 429 rate_limited with a Retry-After header in seconds. Wait that long, then carry on; there’s no penalty for hitting the limit.

Headers

NameTypeDescription
X-RateLimit-LimitintegerRequests allowed per minute: 600.
X-RateLimit-RemainingintegerRequests left in the current window.
X-RateLimit-Resetunix timeWhen the window has fully refilled.
Retry-AftersecondsOnly on a 429: how long to wait before trying again.

Back off on a 429

curl -i https://api.crestora.example/v2/lanes \
  -H "Authorization: Bearer $CRESTORA_TOKEN"
async function getWithRetry(path) {
  const res = await fetch(BASE + path, {
    headers: { Authorization: `Bearer ${token}` },
  });
  if (res.status === 429) {
    const wait = Number(res.headers.get("Retry-After"));
    await new Promise((r) => setTimeout(r, wait * 1000));
    return getWithRetry(path);
  }
  return res.json();
}

Basics

Errors

Crestora uses plain HTTP status codes. A 2xx worked, a 4xx means something in the request needs changing, and a 5xx is on us and safe to retry after a short wait.

Every error has the same shape: a type to switch on, a message written for people, and for validation errors the field at fault. Quote the request_id when you write to support.

StatusTypeWhat it means
400invalid_requestThe JSON or a parameter couldn’t be read.
401unauthenticatedNo token, or one that has expired or been revoked.
403insufficient_scopeThe token lacks a scope; the message names it.
404not_foundNo such object, or one you can’t see.
409stage_conflictThe move isn’t allowed yet, such as into Launch with a version still awaiting approval.
422validation_failedA field failed a check; see error.field.
429rate_limitedOver 600 requests a minute. See Rate limits.
500server_errorSomething broke on our side. Retry with a growing wait.
503unavailableBriefly down for maintenance. Retry after Retry-After.

Basics

Pagination

List endpoints return pages of up to 100 objects, newest first, with a cursor for the next page.

Pass the next_cursor back as cursor until has_more is false. Cursors stay valid for 24 hours.

Query parameters

NameTypeDescription
limitintegerHow many objects to return, from 1 to 100. Defaults to 25.
cursorstringThe next_cursor from the previous page.

Update or move a lane

PATCH/lanes/{id}

Changes a lane’s title or launch day, or moves it to another stage. A move through the API is the same as dragging the lane’s marker in the app: it goes into the lane’s history, and the crew hears about it once.

A lane can’t move into launch while a version is still waiting for approval. You’ll get 409 stage_conflict, listing the versions that are holding it.

Scopelanes:write

Path parameters

NameTypeDescription

Resource

Sparks

A spark is anything caught before it’s a plan: a note, a link, an image or a voice memo. Sparks land on your inbox board, or straight on a lane’s Sparkboard.

Crestora groups related sparks into constellations on its own servers, usually within a minute; constellation_id fills in when it does.

Launches

A launch sends a lane out to one or more channels at a set time, with a checklist built from its Blueprint and, if you like, a launch room for the crew.

Schedule a launch

POST/lanes/{id}/launches

Schedules a lane’s launch. The lane must be in the launch stage with its versions approved. Channels come from your connected integrations: up to 14 on Studio and Crew, one on Solo.

Scopelaunches:write

Events

Webhooks

Webhooks tell your server when something happens on a lane, so you don’t have to keep asking.

Add an endpoint under Settings → Webhooks, pick the events you want, and we’ll POST each one to it within seconds. Endpoints must use HTTPS.

Events

Four events cover the moments most tools care about. Each delivery is a POST with a JSON event; its data holds the object that changed.

EventSent when
lane.stage_changedA lane moves to another stage, in the app or through the API.
version.approvedA version gets its final approval.
launch.liveThe first channel of a launch goes out.
recap.readyAn Afterglow recap is ready, on day 1, 7 and 30.

Answer with any 2xx within 10 seconds and do slow work afterwards. Deliveries that fail are retried with a growing wait for 24 hours, and the same event can arrive twice, so use its id to skip repeats.

Verifying signatures

Every delivery carries a Crestora-Signature header with a timestamp t and a signature v1: an HMAC-SHA256 of the string t.body, signed with your endpoint’s secret. Check it before you trust anything in the body.

  1. Split the header on commas to get t and v1.
  2. Build the signed string: t, a full stop, then the raw request body, byte for byte.
  3. HMAC it with SHA-256 and your endpoint secret, and compare the result with v1 in constant time.
  4. Reject the delivery if t is more than five minutes old.

Find each endpoint’s secret under Settings → Webhooks. Rolling it keeps the old secret valid for 24 hours, so you can deploy without dropping deliveries.

Check a signature

# t and v1 come from the Crestora-Signature header
payload="$t.$(cat body.json)"
expected=$(printf '%s' "$payload" \
  | openssl dgst -sha256 -hmac "$CRESTORA_WEBHOOK_SECRET" \
  | sed 's/^.* //')
[ "$expected" = "$v1" ] && echo "verified"
import crypto from "node:crypto";

function verify(header, rawBody, secret) {
  const { t, v1 } = Object.fromEntries(
    header.split(",").map((kv) => kv.split("=")),
  );
  const expected = crypto
    .createHmac("sha256", secret)
    .update(`${t}.${rawBody}`)
    .digest("hex");
  const fresh = Date.now() / 1000 - Number(t) < 300;
  if (!fresh || expected.length !== v1.length) return false;
  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(v1),
  );
}
import hashlib
import hmac
import time

def verify(header, raw_body, secret):
    parts = dict(kv.split("=", 1) for kv in header.split(","))
    signed = f"{parts['t']}.".encode() + raw_body
    expected = hmac.new(secret.encode(), signed,
                        hashlib.sha256).hexdigest()
    fresh = time.time() - int(parts["t"]) < 300
    return fresh and hmac.compare_digest(expected, parts["v1"])
